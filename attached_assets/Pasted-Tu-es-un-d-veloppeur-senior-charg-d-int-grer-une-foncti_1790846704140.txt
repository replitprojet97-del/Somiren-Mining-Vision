Tu es un développeur senior chargé d'intégrer une fonctionnalité d'assistance documentaire IA dans mon application existante.

IMPORTANT :

- L'application existe déjà et fonctionne.
- L'espace Utilisateur existe déjà.
- L'espace Admin existe déjà.
- Le rôle ADMIN existe déjà.
- Je ne veux PAS créer un nouveau système d'authentification.
- Je ne veux PAS reconstruire l'application.
- Je ne veux PAS supprimer ou casser les fonctionnalités existantes.
- Je veux ajouter une fonctionnalité supplémentaire dans l'espace ADMIN.
- L'application est développée avec Replit et hébergée sur Render.

==================================================
OBJECTIF

Ajouter dans l'espace ADMIN un "Assistant documentaire IA".

Son rôle initial est volontairement limité.

L'IA doit uniquement :

1. Recevoir un prompt écrit par un ADMIN.
2. Générer le contenu d'un document demandé.
3. Produire un brouillon.
4. Permettre à l'ADMIN de consulter et modifier le brouillon.
5. Permettre à l'ADMIN de valider le document.
6. Après validation, permettre à l'ADMIN de choisir l'utilisateur destinataire.
7. Envoyer le document validé dans l'espace de cet utilisateur.
8. Créer éventuellement une tâche associée au document.

L'IA ne doit PAS envoyer elle-même le document.

La validation finale doit toujours être effectuée par l'ADMIN.

ÉTAPE 2 — INTERFACE ADMIN

Ajouter dans l'espace ADMIN une nouvelle section :

"Assistant documentaire IA"

Cette section doit permettre à l'ADMIN de :

- sélectionner un utilisateur ;
- écrire un prompt ;
- générer un document ;
- consulter le brouillon ;
- modifier le contenu ;
- régénérer le contenu ;
- télécharger le document ;
- valider le document ;
- envoyer le document à l'utilisateur.

Exemple de prompt :

"Crée une lettre destinée à Jean Dupont lui demandant de fournir une pièce d'identité, un justificatif de domicile et ses relevés bancaires des trois derniers mois."

L'interface doit rester cohérente avec le design existant.

Ne pas créer une nouvelle interface indépendante de l'application.

==================================================
ÉTAPE 3 — GÉNÉRATION IA

Créer un service backend dédié à l'IA.

Exemple :

AIService

ou une architecture équivalente.

Le frontend ne doit jamais appeler directement l'API IA.

Flux :

ADMIN
→ FRONTEND
→ BACKEND
→ AI SERVICE
→ API IA
→ BACKEND
→ FRONTEND

La clé API doit rester exclusivement côté serveur.

Ne jamais mettre la clé API dans le frontend.

Ne jamais écrire la clé directement dans le code.

Utiliser une variable d'environnement :

AI_API_KEY

Prévoir également une variable pour le modèle :

AI_MODEL

ÉTAPE 4 — FOURNISSEUR IA

Pour la première version, utiliser une API IA externe compatible avec une utilisation gratuite lorsque les limites gratuites le permettent.

Créer une couche d'abstraction afin de ne pas rendre toute l'application dépendante d'un fournisseur précis.

Par exemple :

AIService

Cela permettra ultérieurement de changer de fournisseur ou de passer à un modèle open-weight auto-hébergé.

ÉTAPE 6 — BROUILLON

Après génération, le document doit avoir le statut :

DRAFT

Il doit rester visible uniquement dans l'espace ADMIN.

L'ADMIN doit pouvoir :

- consulter ;
- modifier ;
- régénérer ;
- supprimer le brouillon ;
- télécharger ;
- valider.

Le document ne doit absolument pas être visible par l'utilisateur tant qu'il n'est pas validé.

==================================================

Ajouter une action claire :

"Valider et envoyer"

Avant l'envoi, afficher un récapitulatif :

Utilisateur destinataire
Titre du document
Type de document
Aperçu
Message éventuel

Demander confirmation à l'ADMIN.

Après confirmation :

1. enregistrer la validation ;
2. enregistrer la date ;

4. associer le document à l'utilisateur ;
5. créer la tâche utilisateur si nécessaire ;
6. rendre le document visible dans son espace ;
7. envoyer une notification à l'utilisateur si le système de notification existe.

Réutiliser l'espace utilisateur existant.

L'utilisateur doit pouvoir :

- voir qu'un nouveau document lui a été envoyé ;
- consulter le document ;
- télécharger le document ;
- voir les instructions associées ;
- éventuellement répondre ou déposer les fichiers demandés si le système de tâches existant le permet.

Ne pas modifier inutilement les autres fonctionnalités de l'espace utilisateur.

==================================================
ÉTAPE 9 — SÉCURITÉ

Respecter les permissions existantes.

Seuls les utilisateurs disposant du rôle ADMIN existant doivent pouvoir utiliser l'Assistant documentaire.

Un utilisateur normal ne doit jamais pouvoir :

- accéder à l'Assistant ;
- générer un document administratif ;
- consulter les brouillons d'un ADMIN ;
- envoyer lui-même un document administratif à un autre utilisateur ;
- appeler directement les routes backend réservées à l'ADMIN.

Les vérifications de permission doivent être effectuées côté backend.

Ne pas se contenter de masquer les boutons dans le frontend.
